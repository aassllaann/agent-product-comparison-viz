
### 第五章 系统架构实现与代码落地

#### 第一节 全栈基础架构与宿主环境搭建

在明确了需求层与算法机制后，系统的技术应用工程落地是验证本文方法论可行性的关键一环。本系统遵循经典的分层 MVC（Model-View-Controller）架构思想，为了在开发效率与高并发运行性能之间取得平衡，我们选用了主流且轻量化的全栈应用生态框架。

在技术栈选型层面，表象展示与系统状态维护层（View & State Layer）依托于基于 Python 的 Web 应用框架 Streamlit 搭建。Streamlit 虽然以极少的前端代码代偿能力著称，但其自带的反应式重新渲染机制及安全的 Session State 字典管理功能（如 `st.session_state` 的流转），极大地适配了对答式人机交互的业务所需。智能推理层（Cognitive Layer）则搭载了基于 OpenAI API 标准规范封装的推理引擎接入模块，代码调用采用了解耦配置（如利用 `config.LLM_MODEL` 和自定义 baseUrl），保证了底层大模型随时可以从云端无缝切换升级。数据的视觉渲染展示层选择了 Plotly 开源生态方案，相较于纯静态的 Matplotlib，Plotly 提供可即时唤醒浏览器硬件加速的 SVG 与 WebGL 热图表渲染，并原生自带 HoverToolTip 交互机制，有效降低了图表组件在前端事件监听方向上的研发成本。为了从根源保证大模型获取参数的准确无偏性并承载防幻觉重任，事实数据管控层选定了 SQLite 作为本地轻量化关系型数据库验证引擎，并引入 SQLAlchemy 作为对象关系映射器（ORM）。这种架构将底层的原生 SQL 隔离重构为纯面向对象的操纵，极大提升了查询复用与字段安全的双重约束力。

对应的物理文件拓扑结构亦严格遵循上述职责解耦。根目录中的 `app.py` 作为应用的生命周期起点兼前端控制器（Front Controller），囊括了所有前端视图路由与会话重置钩子；核心识别挂载点分配在 `category_detector.py` 以隔离单纯的意图 NLP 解析动作；而全部针对多品类的专家知识过滤法则与打分策略被剥离收敛至 `electronics_agents.py` 内部。通过合理的项目树切割，保障了不同技术栈组件能够高内聚低耦合地协同运转。

#### 第二节 面向对象的领域多 Agent 模块编程

单一庞大 Prompt 和生硬代码混排的 Agent 设计难以在商品品类繁杂的电商场景中维系。因此，本论文引入了面向对象编程（OOP）的核心设计理念重塑整个系统的代理基底引擎。

系统首先在 `base_agent.py` 文件中提取了一套被命名为 `BaseProductAgent` 的高度抽象基类。该基类使用抽象方法（`@abstractmethod`）以及字典工厂规范了诸如“获取特定数据库模型连接”、“回吐评分轴名称”等各子类必须履行的契约协议。尤为精髓的是，基类中通过模板方法模式（Template Method Pattern）统一封装了核心生命周期方法（`handle_chat_generic`）。在这条固化的流水线上，大模型提示词注入与解析、依据用户预设过滤条件发起 ORM 映射搜索（`filter_candidates` 与降级的 `fallback_search`）、拼接多品类通用排序甚至终审结果给回 LLM 输出“购买理由”这四个主要步骤，被完全沉淀到底层。这在宏观上避免了不同类别商品查询操作时的巨量重复劳动。

基于此坚实基座，诸如同属 `BaseDbAgent` 派生类的 `CameraAgent` 及 `PhoneAgent` 展现了良好的多态性（Polymorphism）。例如，`CameraAgent` 仅需重写自身的抽象方法 `get_specific_dimensions()`，并按自身物理特质返回包括 “便携性 (Portability_Score)”、“低光画质 (LowLight_Score)” 及 “视频能力 (Video_Score)” 在内的独特专属维度及权值向量；而 `PhoneAgent` 返回的则是“续航”与“性能”等轴心。由于所有运算流被隔离，后续加入例如“无人机”这一新品类时，仅需继承并填充少量参数集即可达成平滑介入。而在微观派生类的集群上方，本系统还在 `multi_agent.py` 内实现了一个名副其实的单例路由中心（Central Dispatcher）——`MultiCategoryAgent`。它维护着一个字典架构的观察者注册表（Register Array），结合策略模式（Strategy Pattern）将前置解析器剥离出的分类枚举值，当做钥匙提取对应子代理内存实例，从而将复杂的对话指令优雅地发片分发至特定的干活节点，确保了复杂领域大模型环境下的绝对执行清晰度。

#### 第三节 商品数据层持久化及建模清理

在数据基石构造层面，确保参数的高可用性和业务隔离度是实现无幻觉推荐系统的底线。本平台在 `models.py` 中运用 SQLAlchemy 的 `@declarative_base()` 装饰器范式完整实现了规范的数据持久化映射构建能力。

通过定义 `class Camera(Base)` 或 `class Laptop(Base)`，每个数据实体类直接对应底层关系表结构。系统除强制囊括通用的例如品牌（`Brand`）、型号（`Model`）、价格（`Price`）及缩略图路径（`image_file`）等基本图文表征属性字段外，还针对该表系结构植入了极其详尽的物理结构化参数（如手机类的电池容量 `Battery_mAh` 与主摄像素 `Camera_MP` 等浮点数声明）以及各维度的直读性能评分槽位。当领域 Agent 发起 `db.query(model_class)` 操作时，框架可无缝地将上层业务指令直接编译为防 SQL 注入的底层关系代码。

为了让这套精巧的底层结构跑出真实有效的结果，ETL（数据提取、转换与加载）前处理清洗程序不可或缺。在早期的离线数据工程脚步中，爬虫模块从全网拉取抓取并形成了几百条高度无组织的宽表 CSV。该阶段采用了批处理脚本通过正则表达式系统性地抹除了原数据在爬取时伴随的制表符回车特殊字符与全角中文符号干扰；针对连续数值的空串数据平滑地实施了类型补全与异常极值归零操作；而诸如“支持”、“不支持”、“无线”等强自然主观词皆由逻辑字典严格映射洗盘转为布尔（Boolean）01 标识并最后导入 `SessionLocal` 自动化映射落盘入库。规范的 ORM 建表配合一次性干净的清洗过滤作业，为前台界面的动态展示提供了源源不断的真理养分。

#### 第四节 生成式 UI 渲染与卡片图表技术互动

当干涩的处理报文向表象展露时，枯燥的数据呈现会大幅削弱普通用户的决策耐心，为此系统的末端输出采用了现代化生成式图形用户界面联动渲染交互机制。

依托 Streamlit 提供的单页重绘应用机制（State-driven UI），系统在 `app.py` 中深度接管了基于 `st.session_state` 维护的暂存属性池设计。一旦核心调度反馈包含数据，即可在容器中渲染具有极高辨识度的深紫色点缀、带边缘模糊圆角轮廓以及悬浮阴影的结构。这套带有明显微拟物（Glassmorphism）设计风格的数据商品卡片由独立的 `render_product_card()` 视图渲染器封装并统一向前端吐出 `<div>` HTML 组件块，避免了原始文本控件干瘪的呈现视觉流。在这个卡片结构里，价格用高保真实体显示，评分指标作为重点 `Badge` 色块浮动展示，且商品底部的推荐理由段落（Reason Box）被精准解析呈现并对系统判断出的长尾核心优势加粗高亮处理。

在最能破除受众盲点认知的互动图表挂载区，系统设计了两大核心观测锚点展示位，均由 `visualizer.py` 提供无头图像支持。挂载位一为全景雷达解析图（Radar Chart）：该组件调用 `Plotly Scatterpolar` 组件构建，内部通过将产品的综合项例如跑分能力、价格折算、便携重量等分值平压缩后，循环闭合首尾坐标拼接形成动态包裹的蜘蛛多边形路径，使各候选设备全域潜能优劣通过阴影的饱满轮廓一目了然。挂载位二则作为能力横向分组对比图（Bar Chart）：利用带有 `barmode='group'` 布局属性算法的主成分专项对峙图代码，其从入围队列中将各型号在同领域的评分垂直堆叠陈列组合。通过精密的 CSS `color` 色盘统一配发管理与 HoverToolTip 事件冒泡监控拦截机制，这套兼具工业美学与强反馈的互动视图使得复杂难懂的性能参数被具象成清晰透明的选购指明灯。

#### 第五节 本章小结

本章从系统开发实战出发，全盘展示了本文模型架构在代码工程层面的实施闭环。从在全栈基础上选定 Streamlit、OpenAI 标准通讯协议与 SQLAlchemy 作为底层运行基石开始，文章深入剖析了面向对象架构在代理抽象、共性剥离以及 `MultiCategoryAgent` 注册表模式调度的具体优势与运用；详细还原了基于 ORM 建表模型带来的多级防幻觉底限安全与 ETL 数据清洗流；最后呈现了利用交互绘图引擎将晦涩的设备评分生成全景雷达与拟态化商品卡片的动态前台技术原理。本章通过对各个组件从幕后逻辑贯通至台前视觉交互的代码脉络的解读，证明了前文提出的分层架构完全具备大规模工业级可落地执行的应用能力。
